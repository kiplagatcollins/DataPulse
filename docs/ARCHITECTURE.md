# GoDBClient — Architecture

Explain how the system is structured and how the pieces connect.

## 1. System Overview

GoDBClient is a desktop application with a strict two-process split inside one binary: a Svelte (Vite) frontend rendered in the OS webview, and a Go backend wired through Wails v3 services. All database knowledge lives in a UI-agnostic core (`internal/driver`, `internal/connpool`, `internal/config`, `internal/metadata`, `internal/query`); the `internal/bridge` package is the only code that knows about Wails. SQL engines (PostgreSQL, MySQL, SQLite, Oracle) speak `database/sql` behind a uniform `Driver` interface; Redis is a separate `KV` capability on the same `Conn` handle. A thin `Catalog` interface normalizes metadata so the sidebar tree is identical across engines.

```text
[Svelte UI] → [Wails bindings] → [bridge services] → [metadata / query services]
                                                            ↓
                                              [connpool manager] → [driver registry]
                                                                     ↓
                                        postgres · mysql · sqlite · oracle (database/sql)
                                        redis (go-redis, KV interface)
                                                            ↓
                                              [OS keychain] ← [config store]
```

## 2. Tech Stack

| Layer | Choice |
|---|---|
| Frontend | Svelte + Vite + TypeScript; `@wailsio/runtime` for events |
| Backend | Go 1.27, Wails v3.0.0 (services + generated bindings) |
| PostgreSQL driver | `github.com/jackc/pgx/v5` via `stdlib` adapter (lib/pq is in maintenance mode) |
| MySQL driver | `github.com/go-sql-driver/mysql` |
| SQLite driver | `modernc.org/sqlite` (pure Go, CGO-free) |
| Oracle driver | `github.com/sijms/go-ora/v2` (pure Go, no Oracle Instant Client) |
| Redis driver | `github.com/redis/go-redis/v9` |
| Secrets | `github.com/zalando/go-keyring` (OS keychain) |
| IDs | `github.com/google/uuid` |
| Tests | Go standard library (`go test ./...`), table-driven; SQLite-backed integration tests |
| Deployment | Native binaries via `wails3 build` (Windows, macOS, Linux) |

## 4. Module Responsibilities

- `internal/driver/` — defines `Driver`, `Conn`, `Catalog`, `KV` interfaces and the registry; each subpackage registers itself in `init()` via blank imports in `main.go`. Owns DSN construction and dialect differences. Must not import Wails, config, or bridge.
- `internal/connpool/` — owns open connections keyed by profile ID; enforces connect-timeout pings and `*sql.DB` tuning (max open/idle, 30 min lifetime). Must not parse SQL or touch UI types.
- `internal/config/` — profile CRUD against `<UserConfigDir>/godbclient/connections.json`; delegates secrets to a `SecretStore` (keychain). Must never persist passwords in JSON.
- `internal/metadata/` — calls `Conn.Catalog()` and shapes tree responses; caches per-connection metadata until refresh.
- `internal/query/` — executes statements: guard check → timeout context → `QueryContext` with dialect paging → JSON-safe row scanning → cancel registry (`queryID → cancelFunc`). Must not know about Wails.
- `internal/bridge/` — Wails service structs; translate binding calls to core services and core errors to strings. No business logic.
- `frontend/` — presentation and local UI state only; all database work goes through generated bindings.

## 5. Data Flow

1. User action (e.g. click Run, expand a tree node).
2. Svelte component calls generated binding (`QueryService.Execute(req)`).
3. Bridge service forwards to the core service with plain Go types.
4. Core resolves the connection from `connpool`, applies guard + context, executes against the driver.
5. Driver returns rows; executor converts to JSON-safe `Result` DTO.
6. Bridge returns the DTO; Wails serializes it; Svelte store updates the grid/tree.

## 6. State Model

- **Frontend stores:** `connections` (profiles + active IDs), `tabs` (open editor tabs), `results` (per-tab result set, page, queryID) — all client-owned UI state.
- **Backend state:** open connections (`connpool`), running queries (`cancel registry`), metadata cache. The backend is the source of truth for anything touching a database.
- **Derived:** total page count from `RowCount`, tree expansion state from metadata responses.
- Server state is never duplicated into the frontend beyond a result page; pagination refetches rather than caching full result sets.

## 7. Key Decisions

- **Wails v3 over v2** — v3.0.0 is GA; services + static-analysis bindings give typed APIs and preserve doc comments; multi-window/events model is cleaner for future panes.
- **pgx/v5 (stdlib) instead of lib/pq** — identical `database/sql` integration, actively maintained, richer types; lib/pq is in maintenance mode.
- **modernc.org/sqlite instead of mattn** — pure Go keeps cross-compilation CGO-free (no per-platform C toolchains).
- **sijms/go-ora/v2 instead of godror** — pure-Go Oracle access without the Oracle Instant Client or CGO, matching the modernc.org/sqlite decision; `database/sql`-compatible.
- **Separate `KV` interface for Redis** — forcing Redis through `database/sql` would be a lie; `Conn` composes optional `Catalog()`/`KV()` capabilities instead.
- **Heuristic guard, not a SQL parser** — string-aware tokenization catches no-WHERE `UPDATE`/`DELETE` with zero dependencies; a real parser is a Phase-2 upgrade if false positives appear.
- **Sentinel errors across the bridge** (`ErrNeedsConfirm`, `ErrNotConnected`, `ErrTimeout`) — the UI can branch on typed conditions (show "run anyway?" dialog, resend with `Confirm: true`).
- **`internal/` core, Wails only in `bridge/`** — a future Bubble Tea TUI or gRPC server can reuse the entire core unchanged.

## 8. Error Handling

| Case | Behavior |
|---|---|
| Connection timeout / unreachable host | `ErrTimeout`-wrapped driver error; profile stays disconnected; UI shows precise cause (DNS, refused, auth) |
| Unknown connection | `ErrNotConnected`; UI prompts to connect |
| No-WHERE `UPDATE`/`DELETE`, `DROP`/`TRUNCATE` | `ErrNeedsConfirm` with warning class; UI modal → resend with `Confirm: true` |
| Statement timeout or user cancel | Context canceled; driver query terminated; UI marks the tab "cancelled" |
| Empty/oversized pages | Page size clamped 1–500; `Truncated` flag set when the engine caps rows |
| Keychain unavailable | Save fails loudly with remediation hint; never falls back to plaintext silently |

Errors are wrapped with `%w` and surfaced to the user; they are never swallowed or only logged.

## 9. Testing

- **Unit:** query guard classification (table-driven: statement × expected verdict), config store CRUD against temp dirs, page-size clamping, JSON-safe cell conversion.
- **Integration:** full catalog + executor round-trip against a real temp SQLite file (tables, FKs, indexes, paging, cancel); PG/MySQL/Oracle paths exercised through interface fakes until CI adds service containers.
- **E2E (later):** `web-app-testing` skill / Playwright against the built frontend for critical flows (connect → browse → query).
- **Required checks:** `go test ./...`, `go vet ./...`, `golangci-lint run` (once configured), `wails3 build` for binding/Frontend compile sanity.

## 10. Build and Deployment

```bash
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0   # once
wails3 setup && wails3 doctor                                # once, check GTK/WebKit deps
wails3 dev                                                   # dev server + hot reload
wails3 generate bindings                                     # after changing service signatures
wails3 build                                                 # production binary in build/bin
```

- Environment variables: none required (all config local).
- Deploy target: native desktop binaries; `-tags gtk3` build for older Linux (Mint 21.x / Ubuntu 22.04).
- Rollback: version-tagged releases; binaries are self-contained and downgrade-safe (config JSON is versioned with a `schemaVersion` field).

## 11. Constraints and Limits

- Result pages are capped at 500 rows and cells are truncated per-type (documented limits, `Truncated` flag).
- Oracle support targets 12c+ for native `OFFSET n ROWS FETCH NEXT m ROWS ONLY` pagination; 11g ROWNUM subqueries are out of scope. Oracle identifiers are uppercased by default — catalog queries must uppercase unquoted names before matching `ALL_*` views.
- Metadata cache assumes single-writer DDL; stale until the user hits refresh.
- Linux requires WebKitGTK 6.0 (GTK4 stack) or 4.1 (`gtk3` tag); WebKitGTK 4.0 distros are unsupported.
- Redis SCAN follows cursor semantics — key listing is eventually consistent, never a blocking full `KEYS`.
- Wails v3 mobile targets are explicitly out of scope.

## 12. Extension Points

- **Bubble Tea TUI / gRPC bridge** — both consume the same `internal/` core; the `bridge/` package is the only Wails-aware code, so alternative frontends add a sibling package, not a fork.
- **New SQL engine (e.g. MS SQL)** — implement `Driver` + `Catalog` in `internal/<engine>/`, blank-import from `main.go`; no core changes.
- **SSH tunnels / TLS profiles** — extend `models.Profile` + DSN builders in each driver; connpool stays unaware.
- **Query history & saved snippets** — new `internal/history` service writing to a local SQLite file; exposed as another bridge service.
- **Full SQL parser for the guard** — swap the `guard.Check` implementation; executor call sites do not change.
